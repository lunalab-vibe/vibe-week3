# page-check

HTML 페이지를 5가지 관점으로 점검하고, 발견한 문제를 심각도별로 분류해 한국어로 보고하는 스킬.

## 언제 사용하나

- 사용자가 "페이지 점검", "page check" 라고 요청할 때
- HTML 파일의 기본 품질/접근성/인코딩을 확인하고 싶을 때

## 점검 대상 선정

1. 사용자가 파일 경로를 지정하면 그 파일을 점검한다.
2. 지정이 없으면 프로젝트에서 `.html` 파일을 찾는다(예: `index.html`). 여러 개면 사용자에게 어떤 파일인지 확인한다.

## 5가지 점검 항목

각 항목을 순서대로 확인한다. 판정 기준과 심각도는 아래를 따른다.

### 1. `<title>` 유무 — 🔴 심각
- `<head>` 안에 비어 있지 않은 `<title>` 태그가 있는지 확인.
- 없거나 내용이 공백이면 🔴. SEO·브라우저 탭·북마크에 영향.

### 2. 깨진 내부 링크 — 🔴 심각
- `<a href="...">`, `<link href="...">`, `<img src="...">`, `<script src="...">` 등에서 **로컬(내부) 경로**를 추출.
- 대상: 상대 경로(`./page.html`, `img/logo.png`) 및 루트 상대 경로(`/about.html`). `http://`·`https://`·`mailto:`·`tel:`·`data:`·`#`로 시작하는 값은 내부 링크 검사에서 제외(단, `#앵커`는 해당 id가 문서에 있는지 별도 확인 가능).
- HTML 파일이 위치한 디렉터리 기준으로 실제 파일이 존재하는지 확인한다. 존재하지 않으면 🔴.

### 3. 이미지 `alt` — 🟡 주의
- 모든 `<img>` 태그에 `alt` 속성이 있는지 확인.
- `alt` 속성이 아예 없으면 🟡(접근성 문제). `alt=""`(빈 문자열)은 장식용 이미지에 허용되므로 문제로 보지 않되, 의미 있는 이미지로 보이면 🟢 제안으로 언급.

### 4. 모바일 viewport 메타 — 🟡 주의
- `<head>`에 `<meta name="viewport" content="width=device-width, initial-scale=1...">` 가 있는지 확인.
- 없으면 🟡. 모바일에서 화면이 축소되어 표시됨.

### 5. 한글 UTF-8 인코딩 — 🔴 심각 / 🟢 제안
- `<meta charset="UTF-8">`(또는 동등한 선언)이 `<head>` 최상단 부근에 있는지 확인.
- 선언이 없고 페이지에 한글이 포함되어 있으면 🔴(깨질 위험).
- 선언이 있지만 `<head>`에서 너무 뒤쪽(다른 콘텐츠 뒤)에 있으면 🟢 제안(가급적 `<head>` 첫 요소 권장).
- 가능하면 파일이 실제 UTF-8로 저장되어 있는지도 확인(BOM/깨진 바이트 여부).

## 점검 방법

- 파일 내용은 Read 도구로 읽는다.
- 내부 링크 존재 여부는 Glob 또는 Bash(`test -f`)로 확인한다.
- 정규식 검색이 필요하면 Grep을 사용한다.

## 결과 보고 형식

한국어로, 아래 형식에 맞춰 보고한다. 심각도 순(🔴 → 🟡 → 🟢)으로 정렬한다.

```
# 페이지 점검 결과: <파일명>

## 🔴 심각 (N건)
- [항목명] 문제 설명 — 위치(줄 번호). 수정 방법 한 줄.

## 🟡 주의 (N건)
- [항목명] 문제 설명 — 위치(줄 번호). 수정 방법 한 줄.

## 🟢 제안 (N건)
- [항목명] 개선 제안.

## 요약
🔴 N건 · 🟡 N건 · 🟢 N건 — 한 줄 총평.
```

- 각 지적에는 가능하면 **줄 번호**와 **구체적 수정 방법**을 함께 적는다.
- 해당 항목이 문제없으면 "✅ 통과"로 간단히 표기하고 목록에서 생략해도 된다.
- 점검만 하고, 사용자가 요청하지 않는 한 파일을 직접 수정하지 않는다. 수정 여부를 마지막에 물어본다.
